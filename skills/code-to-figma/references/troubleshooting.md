# Troubleshooting

When a rebuild looks wrong, look up the symptom in this table first. Most of these are already handled in the tools; if a row marked "Handled:" shows up again, first check whether it is a new case.

| Symptom | Cause | Fix |
|---|---|---|
| Animations don't finish; content is stuck in its initial state | When the browser pane is not in the foreground, the page is a hidden tab, and neither `requestAnimationFrame` nor CSS animations run | `__alSettle()` finishes one-shot animations |
| Marquee or carousel text is missing | Infinite looping animations were finished at their end point, where the content has already slid out | `__alSettle(['.marquee_inner', ...])` stops them at the start point; positions set by JS (inline transform) are reset to zero too |
| Extraction hangs and never returns | In a hidden tab, `Image.decode()` never resolves | Handled: al-extract.js uses `fetch` + `createImageBitmap` instead |
| A countdown or polling overwrites the state | Timers are still running | Call `__alFreeze()` right after setting up the state |
| Changing the store does nothing or throws | The store is wrapped in a readonly proxy (Vue `readonly()`) | Change `obj.__v_raw`, or use the store's actions |
| Popups or toasts are not extracted | They are teleported/portaled outside `#app` | `__alExtract` extracts the whole viewport; fixed elements are lifted to the screen's root level |
| `framework` in `stats.json` is null, with the warning "No component info" | It is running a production build (same for Vue and React), or the framework has no adapter yet | Use the dev server (web-capture.md "1. Start the project"); for frameworks without an adapter, only repeated structures are detected |
| React buttons are named after an outer component (e.g. `Tooltip`, `ThemeProvider`) | A custom wrapper component takes the children's props and creates a separate element of a different type (instead of returning it as is or using `cloneElement`), so it can't be recognized as just a wrapper | Make the wrapper return `children` directly, use `cloneElement`, or use `asChild`; if none of these work, add the name to `REACT_BUILTIN` in al-extract.js |
| Next.js Server Components have no name; only repeated nodes like `Item/li` remain | React 18 (Next 14 and earlier) dev builds have no Server Component names | Upgrade to Next 15 or later; if you can't, accept repeated-node detection, or turn the blocks you want as components into client components |
| Layer names are gibberish like `radix-_r_1_` or `:r1:` | Handled: ids auto-generated by React `useId`, Radix, Headless UI and MUI are not used as names | If one shows up again, add its prefix to `GENERATED_ID` in al-extract.js |
| An icon becomes a big color block or is misplaced | With `<svg><use href="#sprite">`, the nested svg loses its size on import | Handled: al-extract.js flattens the sprite content and converts the viewBox |
| Text wraps onto two lines | Figma's text is slightly wider than the browser's, so a fixed width is just too narrow | Give single-line text its natural width + 1; set the line height to the browser's height |
| Text becomes bolder or narrower | The font family has width variants such as Condensed in Figma, and one gets picked when choosing the weight | al-build.js only picks weights from the normal width |
| Content in a scrolling area is misplaced | The content is scrolled left, so the child starts before its parent | Make these children absolute, keeping their real position; clip the container |
| Rotated or mirrored images are missing or face the wrong way | Merging outer frames drops the transform; mirroring is treated as rotation | Elements with a transform are not merged; axis-aligned transforms are reapplied with relativeTransform |
| The reference screenshot doesn't match the extracted state | The screenshot tool returns the previous frame | Take two screenshots in a row and use the second |
| The same component at different sizes is turned into one | The component key doesn't include size | The key includes the root size, so different sizes become variants |
| Pseudo-elements (`::before`/`::after`) are missing | They are not in the DOM | al-extract.js extracts absolutely positioned pseudo-elements (including their text and background color), and small inline-block `::before` color blocks (list bullets); add other non-absolute ones by hand and list them in the report |
| After importing the data SVG, text is empty and `JSON.parse` fails | Several upload URLs were POSTed in parallel, and some imported text had no content | Upload one at a time (1–2 seconds apart); before building, check that the c/d text is non-empty before deleting the data frame |
| The root frame becomes tens of thousands of px tall | When the whole page scrolls, `#app` carries the full scroll height, and a Hug root gets stretched | `fitViewport` in al-build.js fixes the root to the viewport size and clips it |
| A whole carousel banner is missing | The swiper wrapper is pushed off screen by a transform, and since its own box is not in the viewport, it is dropped | Handled: al-extract.js now keeps it if any child is on screen, and calls `swiper.autoplay.stop()` before capturing |
| An instance with replaced text gets truncated ("Curse of Anub") | The main component uses the fixed width from the first data set, and the size API can't change the instance's children | Fix the main component directly: make the text's frame Auto Layout, set the text to Fill + auto height, and remove truncation; this takes effect in all instances |
| Text becomes extra-bold Display Black | The font family has optical-size variants such as Display, and with the weight resolved to 400, one of them gets picked first | Handled: al-build.js excludes Display/Caption/Subhead variants |
| Input values or placeholders are missing | The value is not in a DOM text node | Handled: al-extract.js builds the text from the content box |
| An svg with a background (round gradient icon button) shows only the icon | The svg is treated as a plain vector, so the background and padding are not extracted | Handled: al-extract.js wraps it in a frame with the background |
| Product images and banners are blurry | The original PNGs are very large | Handled: al-extract.js caps images at 1600px and turns large opaque images into JPEG; al-pack.py splits images into separate files for upload |
| The data SVG is abnormally large; a card has hundreds of extra vector layers | A hidden icon sprite (only `<symbol>`) is extracted as an icon | Handled: al-extract.js skips svgs that only contain symbols; check this first when `jsonKB` in `stats.json` is much larger than for similar screens |
| Chinese text in code or data turns into garbled text in Figma | `atob` only understands Latin-1 | Handled: al-pack.py converts non-ASCII to `\uXXXX` |
| Column widths in a row are wrong; spacing is missing | Figma's Fill subtracts each child's padding and then splits the space evenly, and it also swallows space-between gaps | al-extract.js calculates this first and keeps a fixed width when it doesn't match the browser width; rows with grow use the actual gap |
| Every bordered frame is 1px larger, drifting more further down | `strokesIncludedInLayout` is on by default, and the padding already includes the border | Handled: al-build.js turns it off |
| Arrows point the wrong way | The svg's own `transform` is not carried over | al-extract.js writes the rotation into the SVG |
| Trapezoid buttons and slanted title bars become rectangles | `clip-path` has no matching Figma property, and the tools don't handle it | Not restored for now; list it in the report |
| Numbers in instances shift left; only the cell with the same value as the main component is correct | Centering relies on the text box; when the instance swaps the text, the box is changed to Hug and aligns left | al-extract.js turns centered content into Auto Layout centering; al-build.js keeps the box when swapping text; `log.drift` catches it |
| Components has lots of v2, v3 copies that are just field containers | Repeated-structure detection turned containers into components too, and states only rely on instance color overrides | Containers that already contain components are no longer wrapped as components; selected, disabled and similar classes on small components become variants, named after the text layer plus the state |
| Components has full-page components whose lower half is empty frames and stretched color blocks | The page root or elements cut by the viewport were made into components, and their off-screen children were not extracted; the card looks fine because the root clips it | Handled: al-extract.js excludes elements cut by the viewport; the audit catches components taller than the screen |
| The right side of the component area is cut off | All variants are laid out in one row and overflow the section | al-build.js wraps to a new row past the shelf width; the audit catches it |
| Checkboxes become the text "on" and lose their checked state | The checkbox's `value` is on, and its native appearance is not in CSS | Handled: al-extract.js draws the box and check mark from `checked`, colored with `accent-color` |
| Right-aligned amounts or totals are cut off | `justify-content: flex-end` was stored as a fixed start padding, so longer text overflows | Handled: al-extract.js aligns to the end instead, with padding taken from the CSS values |
| Fields in a row are misplaced; right-side content touches the edge | A `flex: 1` element collapsed into text has no grow, so it shrinks to Hug when the text changes | al-extract.js keeps grow on the text; when a row has several grow texts of different widths, it keeps the browser widths, because Figma's Fill splits evenly |
| A scrolled list shrinks to a thin strip | After the content became absolute, nothing stretches the parent, and Hug doesn't count Fill children | al-build.js doesn't Hug the width of vertical stacks that have Fill children; the audit catches it |
| The end of input text is cut off | The text width follows the browser, but Fill makes the container narrower | al-build.js gives children that fill the container a STRETCH constraint; the audit catches text wider than its clipping container |
| A small button or badge is covered by a nearby overlay, and only it is dimmed | Its z-index is set on a deeper layer and compared against the outer overlay; Figma's layer tree can't move a single child out | The tools set the whole layer's order by the content covering the largest area, so small elements may be covered; list it in the report |
| A card's sheen or diagonal stripes end up above the image | A deep in-flow element has a higher z-index, or `mix-blend-mode` was not carried over | Handled: al-extract.js orders layers by the browser's paint order, and blend modes are carried into Figma |
| Multi-line text wraps in different places | The text box uses the text's own width, narrower than the container | Handled: al-extract.js uses the container width; `line-clamp` maps to Figma's max lines |
| Library icons are all black | The color is in a class or currentColor, not in the SVG markup | Handled: al-extract.js reads the computed style; multicolor icons are not recolored |
| The marquee position is off from the screenshot by some distance | The animation ends and restarts, or `transitionend` triggers the next segment | `__alSettle` only finishes entrance animations within 1.5 seconds, pauses the rest, and turns off all transitions |
| Dark gradients have whitish edges | Figma's gradients don't use premultiplied interpolation, so the RGB of transparent stops gets mixed in | Handled: al-extract.js gives transparent stops the color of their neighbor |
| Tailwind projects have wrong text widths and different wrapping | `ui-sans-serif` is not a real font and gets replaced with Roboto | Handled: al-build.js replaces the system font stack with Inter; mention this in the report |
| Dev panels or mock toolbars are captured in the screen | UI that only exists in mock mode | List their selectors in `hide` in the config |
| The data SVG is over 2MB and al-pack.py stops | Images are already split out; what is left is the layout itself: the page is too long or has too many nodes | Split it into several viewport-height screens and capture again. Don't raise the limit: importing a data SVG makes memory usage spike |
| The Figma file runs out of memory and must be opened in recovery mode | Data SVGs for many screens were uploaded at once, or screens were rebuilt after a mass deletion | Stop as scale-guard.md says. After that, do one screen at a time, and ask the user to save a version before deleting and rebuilding |
| `__alBuild` reports "Temporary frames from another screen are still on the page" | Data or images for several screens were uploaded in one batch | Delete the other screens' `ALDATA-` and `ALIMG-` frames, upload one screen at a time, and run again |
| `log.warn` contains "uploaded image not found" | An image was not uploaded, or its file name was changed during upload | Redo the whole screen: re-upload all of this screen's images and its data SVG with the file names al-pack.py lists, and rebuild with `replace`. Re-uploading only the missing image doesn't work: by the time the build finished, this screen's other image frames were already deleted |
| Two sections overlap | The component section is positioned at the first screen, and later screens make the main section wider | al-build.js moves the component section aside after each build; if it covers other nodes it only warns, and the audit catches it |
| Icons are all black or missing, and `stats.json` says icons are empty | The e2e setup blocks the icon CDN, or lazy-loaded icons haven't arrived yet | Allow the static asset domain and capture again; al-capture waits 3 seconds for lazy-loaded icons |
| Table headers or dark backgrounds are covered by a light block | A `z-index: -1` pseudo-element in a parent with no stacking context is painted below the parent's background by the browser | Handled: al-extract.js lifts it to the bottom of the nearest stacking context |
| Table lines become 2px | With `border-collapse`, adjacent cells share one line | Handled: al-extract.js keeps the line on one side only |
| A tab's small triangle becomes a square, a checkbox's check becomes an L shape, a small red tag loses its slant | Triangles drawn with CSS borders and rotated elements can't be drawn with frames | Handled: al-extract.js turns such elements into vectors when they have no children; rotated containers with children still follow their outer box |
| Numbers after truncated text are pushed out of the card | Range measures the full width of the untruncated text | Handled: al-extract.js limits the width of truncated text to the container |
| A whole block shifts down by a fixed distance | A zero-size wrapper that only holds absolutely positioned content is counted in layout, adding extra space | Handled: al-extract.js keeps zero-size children out of layout |
| A centered block sits off to one side | The parent has different left and right padding, so the child wrapped in Align is centered in an asymmetric box | Handled: al-extract.js decides centering inside the Align box instead |
| The selected item is as dim as the others | The state relies only on opacity; the main component was built from a semi-transparent item, and the selected item, which doesn't set opacity, inherits it | Handled: al-build.js resets instances that don't set opacity to 1 |
| After a rebuild, text in an instance sticks to the top or left edge | The old main component positioned it with padding, the new data centers it, and the instance only changed the padding | Handled: al-build.js overrides the alignment too |
| A widescreen component set overflows the Components section | Two 1920-wide variants sit side by side, with no wrapping when they are first combined | al-build.js wraps when combining, and components wider than the shelf widen the shelf; the audit catches it |
| Text in one header column is off to one side; only the column as wide as the main component is correct | The same component is used at different widths, and the inner frame in the instance can't be resized | al-build.js sets the only child that fills the outer frame to Fill; when the inner frame has several children it still shifts, and `log.boxes` lists it |
| An SVG background image is scaled up and cropped, or an image's glow is missing | When `<img>` loads an SVG, the browser scales it proportionally into the box; the glow of `filter: drop-shadow` follows the shape, but Figma's shadows only follow the rectangle | al-extract.js draws a separate image that looks the way the browser shows it; the same goes for object-position, none and scale-down |
| The diff percentage is high, but you can't tell where | Details are not visible in the full thumbnail, so it's easy to guess the wrong cause | Look at the `<ID>-diff<n>.png` files al-diff.py writes, then check in the source which CSS that part uses; put it in the report only after confirming |
| The color binding ratio suddenly drops a lot | Once icons actually load, there are many more vectors, and their colors are not in the design system | Check `unboundVectors` in the audit; if the ratio excluding icons didn't drop, binding is not broken |
| Components is full of unused old main components | After screens are rebuilt, old main components and variants stay on the shelf | Run cleanup-components.js and review the list first; only after the user agrees and has saved a version, paste the list's `ids` into `APPROVED_IDS` to delete them. The list already includes inner components used only by old components, so one pass cleans everything up |
| After deleting old components, new unused components are listed a while later | For a short time after a deletion, Figma still counts instances inside deleted components in `getInstancesAsync` | List again after a few minutes; the 0.4.0 cleanup-components.js lists inner components the first time |
| A radial gradient's circle is too large, too small, or off center | Figma's gradient coordinates use a unit square and were not converted from the CSS shape, size keywords and position | Handled: al-extract.js computes the radius and center from the CSS, and al-build.js builds the gradient at the computed position |
| A carousel stops on some middle slide, and the banner differs on every recapture | Swiper autoplay; changing slides relies on `requestAnimationFrame`, so it can't change slides after `__alFreeze` | al-capture calls `__alResetCarousels()` before freezing, so autoplaying carousels go back to the first slide; carousels that are not autoplaying are left alone, and the slide `card.run` switched to is kept |
| Block positions after a click differ by a few px each time | Extraction ran before smooth scrolling stopped | al-capture waits for the page and inner scroll containers to stop, up to 3 seconds |
| Content in an instance gets longer and overlaps the next item (marquee) | A nested instance's frame can't be resized and stays at the main component's width | When al-build.js can't resize it, it sets Auto Layout frames that are Hug in the data to Hug, so the content can expand |
| A rebuild is blocked because "the screen was changed", but nobody touched it | Screens built later updated a shared main component, so the fingerprints of earlier screens changed too | After building, al-build.js recomputes the fingerprints of screens that were not changed before the build; screens built by older tool versions may still be blocked once on their first rebuild; confirm nobody changed them, then pass `force` |
| The diff percentage differs on every rerun, and the same area has different content each time | Mock random values are generated in a service worker, and `SEED_RANDOM` only fixes the page's `Math.random` | Capture once more and compare; treat the areas that change as noise and explain this in the report; to pin them down, switch to fixed data in the mock layer |
| Progress bars are all full, or the same component always has the same length | The Plugin API can't change the width of a frame inside an instance | al-build.js changes the instance's padding and gap; the length comes from the parent's padding |
| A whole title row with a single line of text is misplaced | The text box is taller than the line height, so it was treated as scrolling content and fell back to absolute positioning | Handled: al-extract.js corrects the text box back to the line height; when an instance's Hug is shorter than in the browser, it is fixed to the browser height |
| Components has a pile of huge carousel items | Third-party containers like Swiper are made into components | Handled: they are on the list of things not made into components; add other third-party containers to `BUILTIN` in al-extract.js |
| Icons have a black square background | The exported SVG is wrapped in a rectangular clipPath, which becomes an opaque frame after Figma imports it | Handled: al-extract.js removes rectangular clipPaths |
| A sticky nav bar is covered by content | Overlapping content can't be laid out with Auto Layout, and the fallback to absolute positioning did not reorder it | Handled: al-extract.js orders everything by paint order |
| Text touches the outer edge; the left padding is missing | When the element was collapsed into text, the outer box coordinates were used | Handled: al-extract.js keeps the left padding |
| Labels with `transform: scale()` have text that is too large | The computed font size doesn't include the transform | Handled: al-extract.js converts the font size using the actual display scale |
| Custom checkbox squares are missing | The square is a `::before` in a flex row, not in the DOM | Handled: al-extract.js extracts `::before` squares at the start of flex rows |
| Short `flex-grow` labels wrap onto two lines | The Fill box is only slightly wider than the text | Use Hug when the width equals the text itself |
| The build reports `Reparenting would create a component set cycle` | A component contains the same component set, so they can't be combined into variants | Handled: al-build.js makes it a standalone component and adds `(nested)` to the name |
| A full-page screen is missing a section, and the node count is much lower than last time | Data didn't come back. It may load only after hydration, or the framework's server cache may still hold results from an old mock | Handled: the tools wait for the network and images to settle; Nitro's swr cache is in `.nuxt/cache`, so clear it after changing the mock port |
| Background or decorative images are missing | `background-image` uses `image-set()` | Handled: al-extract.js takes the highest-resolution image |
| Video areas are black | Figma can't hold video, so the tools only draw the background color | Handled: al-extract.js captures the current frame; if the video hasn't loaded yet it is still black, so scroll to it first or use full-page mode |
| The same component has different layout directions on mobile and desktop, and text overlaps | The main component is shared, and an instance can't change the layout direction | Handled: the layout direction is part of the component structure, so they become different variants |
| Faded edges and watermarks become solid color blocks | Gradient or bitmap `mask-image` has no equivalent, and the tools don't handle it | Not supported yet; list it in the report (icons with SVG masks are supported, see below) |
| A whole sidebar or nav bar is missing, leaving only the background color | A `z-index: -1` pseudo decoration layer is placed above the content | Handled: al-extract.js carries over the pseudo-element's z-index |
| The whole screen has no color: no backgrounds, borders or badge backgrounds, and all text is black; the color stats returned by `__alBuild` are empty | The palette is defined in `oklch()` (Tailwind 4, frappe-ui, etc.); Chrome's computed style returns `color(srgb …)`/`oklch()`, and older versions only understood `rgb()` | Handled: 0.5.0 converts them to sRGB with a canvas. If there is still no color, run `getComputedStyle(el).backgroundColor` on the page to see the format, and add it to `color()` in al-extract.js |
| Icons become solid color blocks (e.g. a bell becomes an orange square) | The icon is an empty `<span>`; the shape is an SVG in `mask-image`, and the color is the background color (frappe-ui, UnoCSS `lucide-*` and `i-*` classes) | Handled: 0.5.0 decodes SVG masks into vectors filled with the background color. Bitmap masks, or masks that cut a sprite with `mask-position`, are not supported yet |
| Text next to dates, times and amounts is off by 5–8px; badges with numbers are narrower than in the browser | The product uses `font-variant-numeric: tabular-nums` (Tailwind `tabular-nums`) for equal-width digits; `openTypeFeatures` in the Figma Plugin API is read-only and can't turn on TNUM, so digits go back to proportional widths | Not restored for now; `log.drift` lists it; explain in the report that tabular numbers cause it. Possible fix: have al-build.js fix this kind of text to the browser width; not yet verified in Figma |
| Every Figma tool returns "reached the Figma MCP tool call limit" | The Starter plan or View/Collab seats get about 20 calls a month, and both `use_figma` and `get_screenshot` count | Stop as scale-guard.md says, and list the finished screens and the ids of temporary frames left on the canvas. Estimate the call count before starting |
| `create_session` returns "could not access the requested file" | The account MCP is signed in with has no access to this file (common case: the file is in a personal account, and MCP is signed in with a work account) | Use `whoami` to see which account it is, and ask the user to share the file with it (can edit), or sign in with another account in the connector |
| Each card needs a different API response, but gets another card's data | In 0.4.0, `setup(context)` doesn't receive the card ID, so the only option is to guess from the capture order | Since 0.5.0, `setup(context, id, card)` receives the card ID, and a card can also define its own `setup` (web-capture.md) |
